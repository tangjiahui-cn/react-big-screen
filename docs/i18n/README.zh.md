# 双语文档

简体中文 | [English](./README.md)

本仓库的文档供中国境内外的人与 agent 阅读，因此范围内每篇文档都维护英文与简体中文两个版本。
英文为默认语言：不带后缀的 `{name}.md` 即英文版，简体中文使用 `{name}.zh.md` 后缀。
本页定义配对约定、检查、引用处理与范围规则；[terminology.md](terminology.md) 是术语真源。

## 修改约定

更新范围内任一篇 md 时，必须在同一改动中同步更新其配对语言版本；
配对版本不存在时，在本改动中创建。
新增、修改双语文档时，还必须在同一改动中同步更新其 `{name}.i18n.yaml`。

文件名约定：
- 英文（默认）：{name}.md
- 简体中文：{name}.zh.md
- 配对清单：{name}.i18n.yaml

例：更新 `README.md` 时同步更新 `README.zh.md` 与 `README.i18n.yaml`；不存在则创建。

## 配对清单

每一对文档都由同目录下的 `{name}.i18n.yaml` 登记，记录了中英两侧的内容哈希：

```yaml
README.md: 9f89db3d4502dea4a0d181799164f304d4976740
README.zh.md: aa66ef1d24a5e2165859e9337273d807dff3d070
```

键是相对清单自身所在目录的文件名，值是 git 存储该文件时会得到的 blob 哈希（`git hash-object`）。
清单由工具维护：用下面的命令重录，不要手工计算哈希。

```
pnpm run verify-translation-pairing                     校验全部配对
pnpm run verify-translation-pairing --staged            仅校验已暂存待提交的配对
pnpm run verify-translation-pairing --write <路径>...   重录指定配对
```

校验已挂入 pre-commit 钩子，并带 `--staged`，因此两侧脱节的配对会直接提交失败，而本次提交未触及的配对不会被重复检查。
`--staged` 两侧都读索引，因此它判定的是这次提交真正会存下的内容 —— 包括被暂存删除的一侧：它已经离开索引，却仍躺在磁盘上。
校验通过时不打印任何内容并以 0 退出；只有失败才写 stderr，只有重录才打回执。
重录必须显式指名对象：不存在「全量重新生成」，所以清单不可能在无人决策的情况下被更新。

## 受管辖的范围

- 配对存在 `{name}.i18n.yaml` 即为**已登记**。
- 已登记：两侧必须都存在，且两个哈希都必须匹配。
- 双侧齐全但没有清单：报错，必须登记。
- 只有单侧且没有清单：视为单语文档，放过。

单语文档是由「缺少对侧」定义的，而不是由一份名单定义的，所以没有豁免文件需要维护。

## 重录是检查点，不是证明

- 两个哈希是一起写入的，所以重录出来的清单必然能通过校验；
- 真正的闸门在它之前那一步：改过的配对不指名就提交不上去，而那一刻正是确认两侧确实一致的机会；
- 不要把重录挂进任何钩子 —— 那会让校验退化成空操作。

## 语言检查

- 每个已登记的配对都存在中英两份 md。
- 每份文档顶部提供 中文/English 切换入口。
- 当前语言不加链接，另一种语言加链接。

## 处理引用

- 配对文档引用其他 md 时，指向引用方语言对应的版本；
- 该语言的版本不存在时，指向已存在的语言版本。

例：`README.md` 指向 `docs/architecture.md`；`README.zh.md` 指向 `docs/architecture.zh.md`。

## 处理范围

- 全部已登记的配对，以及工作区里任何双侧齐全的 `{name}.md` / `{name}.zh.md` 配对，都在范围内；
- `--staged` 把一次校验收窄到索引里存在变更的配对，它只改变一次运行覆盖多少范围，不改变施加其上的规则；
- 没有对侧的 `.md` 属单语文档，放过；
- [terminology.md](terminology.md) 是术语真源，单语维护，有意不配对。

例：`AGENTS.md` 与 `CHANGELOG.md` 是当前的单语文档。

# Git 提交信息中禁止 AI 归属标识

用于约束提交信息中不得出现任何第三方 AI agent 的归属标识，避免提交历史中出现工具归属噪声。

## 适用范围

本规范约束**提交信息**，适用于一切生成或改写提交对象的操作：

- `git commit`，含 `--amend`；
- `git rebase` 过程中的 reword、squash 合并后的提交信息；
- `git merge`、`git revert`、`git cherry-pick` 生成的或随后被人工编辑过的提交信息；
- 任何以脚本或工具批量改写历史提交信息的操作。

PR 标题与描述、issue 评论、tag 说明等对外文本不在本规范范围内，如需约束应另行规定。

## 禁止内容

包括但不限于：

- `Co-Authored-By:`、`Signed-off-by:`、`Assisted-by:` 等 trailer 指向 AI 工具；
- `Generated with` / `Generated by` / `Made with` / `Powered by` 等归属语句；
- 正文或 footer 中构成归属声明的工具提及。

判定原则：只要语句在表明“本次提交由某 AI 工具生成/参与/署名”，即视为归属标识。工具范围不以枚举为限，任何 AI 工具（Claude、Copilot、Cursor、Gemini、Codex、Aider、Windsurf 等）同样适用。

### 判定测试

拿不准时用「替换测试」：把工具名换成一个人类贡献者的名字，看句子是否变成一句署名声明。

| 原文                                        | 替换后              | 判定               |
| ------------------------------------------- | ------------------- | ------------------ |
| `Co-Authored-By: Claude <noreply@anthropic…` | `Co-Authored-By: 张三` | 成为署名声明，违规 |
| `Generated with Claude Code`                | `Generated with 张三`  | 成为署名声明，违规 |
| `This change was written by Claude Code.`   | `…written by 张三.`    | 成为署名声明，违规 |
| `fix: handle claude code MCP timeout`       | `fix: handle 张三…`    | 替换后语义不通，合规 |

替换后仍读作“某人生成/参与了本次提交”的，就是归属标识；只在描述技术上下文（接口名、依赖名、报错来源）的，不属于归属标识。

## 允许例外

因技术原因提及某工具名，且该提及不构成归属声明的，不属于禁止范围。例如：

```text
fix: handle claude code MCP timeout
```

```text
this hung on the MCP timeout bug in Claude Code
```

例外仅在工具名作为技术上下文出现时成立；一旦句子在说明“谁生成了本次提交”，无论出现在 trailer、主题行还是正文，都按归属标识处理。

## 发现后如何处理

1. 优先从源头关闭：若归属标识是工具自动追加的（提交信息模板、agent 的 attribution 配置等），先在工具配置中关闭该输出。否则删除后会被重新写入，陷入反复修改的循环。
2. 删除归属行或归属语句，只保留描述变更本身的内容。
3. 如果工具名是技术上下文所需，改写为不构成归属声明的表述。
4. 修改完成后重新自查（脚本 + 替换测试），确认无命中再提交。

示例：

```text
# 不合规：trailer 署名
feat: add login flow

Generated with Claude Code
Co-Authored-By: Claude <noreply@anthropic.com>

# 不合规：正文散文式署名
feat: add login flow

This change was written by Claude Code.

# 合规
feat: add login flow
```
